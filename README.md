# xcpd

Unity IL2CPP 游戏的 **ESP 透视 + 鼠标自瞄**，Rust 写成，编译成单个 DLL 注入游戏进程。

> 完整实现原理、偏移挖掘方法、以及**迁移到其他游戏的 checklist** 见 → **[实战教程](docs/Unity-IL2CPP-ESP与自瞄-实战教程.md)**

---

## 特性

| 模块 | 能力 |
|---|---|
| **ESP** | 方框、射线、血条、昵称、棍人骨架、敌我染色、顶部绘制/背敌人数 |
| **自瞄** | 模拟鼠标位移（不写视角）、自适应灵敏度在线学习、FOV / 平滑 / 速度可调、瞄头或瞄脚、预判提前量 |
| **目标筛选** | 只瞄敌人、**人机（AI/bot）单独放行**、按住触发、目标粘滞（防准心横跳） |
| **防抖** | 死区、单帧限步、增益封顶、屏幕超前补偿、位置平滑（治人机低频坐标"一卡一卡"） |
| **边界处理** | 探头横向补偿、蹲下/趴下姿态跟随、幽灵框过滤、加载期崩溃防护 |

## 快速开始

### 1. 构建

```bash
cargo build --release
# 产物：target/release/xcpd.dll
```

### 2. 注入

用任意支持 `LoadLibrary` 的注入器把 DLL 打进游戏进程（hudhook 自带 injector，或用通用注入器选 LoadLibrary 模式）。

### 3. ★ 验证加载的是最新构建

**注入后第一件事：看日志的第一行版本指纹。**

```
=== xcpd ESP 启动 【v126·人机自瞄放行+人机诊断】 ===
```

日志路径固定：`C:\csgo_hook.log`

> 指纹不是最新 → 说明注入的不是你刚构建的那个文件。
> 这个习惯能省掉大量"明明改了代码却没效果"的排查时间。

### 注意：游戏运行时无法覆盖 DLL

如果游戏正加载着这个 DLL，`cargo build` 会报：

```
error: failed to remove file `target\release\xcpd.dll`
Caused by: 拒绝访问。 (os error 5)
```

把它重命名掉即可（Windows 允许重命名已映射的文件）：

```powershell
Rename-Item target\release\xcpd.dll xcpd_prev.dll
```

## 使用

| 操作 | 作用 |
|---|---|
| `Insert` | 开关菜单 |
| **鼠标右键**（可改） | 自瞄触发键 —— 菜单里点「按键: …」那一行，然后按任意键即可改绑 |

自瞄在**菜单打开时一律不工作**，避免调参时乱动。

## 项目结构

```
src/
├── lib.rs       入口：DllMain / Present hook / 渲染循环 / 菜单绘制
├── memory.rs    内存读写 + IL2CPP 导出 API + 视图矩阵数学
├── offset.rs    ★ 所有硬编码偏移集中在这里（每条附实测来源）
├── config.rs    菜单配置项与默认值
├── data.rs      读游戏数据：角色枚举、快照构建、位置/姿态平滑
├── esp.rs       ESP 绘制（框 / 骨架 / 血条 / 昵称）
├── aim.rs       自瞄：目标选择 + 鼠标位移计算
└── log.rs       限流日志
```

**划分原则**：`lib.rs` / `memory.rs` / `log.rs` 与具体游戏无关，换游戏几乎不用改；
`data.rs` / `offset.rs` / `esp.rs` / `aim.rs` 是游戏相关的，需要重新挖偏移。

## 维护须知

- **偏移会随游戏更新失效**。改偏移只需要动 `offset.rs`，不要散落到各处。
- 挖到新偏移后，**把实测来源写进那条常量的注释里**（例如"实测：0x7F8 是坐标，0xA4 读出来是常量 (0,1,0)"）——下次别人（或未来的你）照着 dump 猜错时，这条注释能救命。
- 写内存类功能（自身加速、内存自瞄）已从项目中移除，现在只保留**纯读取 + 模拟鼠标输入**。
- 判断代码是否还能删：`cargo check --message-format=short` 里的 `never used` 清单就是最可靠的死代码清单。
